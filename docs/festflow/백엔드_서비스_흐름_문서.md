# FestFlow 백엔드 서비스 흐름 문서

이 문서는 FestFlow 백엔드의 `Service` 계층이 어떤 책임을 갖고 있는지, 주요 public 메서드가 어떤 역할을 하는지, 그리고 `Frontend -> api.js -> Controller -> Service -> Repository/외부 연동 -> DTO -> Frontend` 흐름이 어떻게 이어지는지 빠르게 확인하기 위한 문서입니다.

코드 기준 주요 위치:

- Frontend API 모음: `frontend/src/api.js`
- Frontend 화면: `frontend/src/pages`
- Controller: `backend/src/main/java/com/festflow/backend/controller`
- Service: `backend/src/main/java/com/festflow/backend/service`
- DTO: `backend/src/main/java/com/festflow/backend/dto`

## 1. 전체 요청 흐름

```text
Frontend Page
-> frontend/src/api.js 함수 호출
-> Spring Controller endpoint
-> Service public method
-> Repository / 외부 API / 파일 저장 / ML 스크립트
-> Response DTO
-> Frontend state 갱신 및 렌더링
```

실시간 갱신이 필요한 기능은 REST 응답 이후 `StreamService`가 SSE 이벤트를 발행하고, 프론트는 `createBoothStream`, `createEventStream`, `createCongestionStream`, `createLostItemStream`, `createReservationStream`, `createStaffStream` 등으로 다시 데이터를 불러옵니다.

## 3. 서비스별 역할과 메서드

### 3.1 `BoothService`

부스 데이터의 조회, 생성, 수정, 삭제, 정렬, 이미지 갱신, 실시간 운영 상태, 혼잡도 계산을 담당합니다. 지도, 홈, 부스 상세, 관리자, 운영자 화면의 기본 데이터 공급원입니다.

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `getAllBooths()` | 전체 부스를 정렬해서 `BoothResponseDto` 목록으로 반환 | `BoothController`, `OpsController`, `AdminDashboardService`, `AnalyticsService`, 프론트 `fetchBooths` |
| `getBoothById(Long boothId)` | 단일 부스 상세 조회 | `BoothController`, `OpsController`, `ReservationService` |
| `createBooth(BoothUpsertRequestDto)` | 관리자/운영자가 새 부스를 생성 | `AdminBoothController`, `OpsController`, `AdminImportService` |
| `updateBooth(Long, BoothUpsertRequestDto)` | 기존 부스 기본 정보 수정 | `AdminBoothController`, `OpsController`, `AdminImportService` |
| `updateBoothImage(Long, String)` | 업로드된 대표 이미지 URL을 부스에 반영 | `AdminBoothController` |
| `updateBoothMenuImage(Long, String)` | 업로드된 메뉴 이미지 URL을 부스에 반영 | `OpsController` |
| `updateLiveStatus(Long, BoothLiveStatusRequestDto)` | 대기 시간, 재고, 운영 메시지 등 현장 상태 수정 | `AdminBoothController`, `OpsController` |
| `reorderBooths(BoothReorderRequestDto)` | 관리자/운영자가 지정한 순서로 부스 정렬 | `AdminBoothController`, `OpsController` |
| `deleteBooth(Long)` | 부스 삭제 | `AdminBoothController`, `OpsController` |
| `getCongestionByBoothId(Long)` | GPS, 예약, 시뮬레이션 상태를 반영한 개별 부스 혼잡도 계산 | `BoothController`, `OpsController`, `FestivalSnapshotService` |
| `getAllCongestions()` | 전체 부스 혼잡도 목록 계산 | `AnalyticsService`, `FestivalSnapshotService` |
| `getMostCongestedBooth()` | 가장 혼잡한 부스를 찾음 | `AdminActionService`, 운영 알림 생성 |

대표 흐름:

```text
StageMapPage / HomePage
-> fetchBooths()
-> GET /api/booths
-> BoothController.getBooths()
-> BoothService.getAllBooths()
-> BoothRepository.findAll()
-> List<BoothResponseDto>
```

```text
BoothDetailPage
-> fetchCongestion(id)
-> GET /api/booths/{id}/congestion
-> BoothController.getCongestion()
-> BoothService.getCongestionByBoothId()
-> GpsLogRepository + BoothReservationRepository + SimulationStateService
-> CongestionResponseDto
```

### 3.2 `EventService`

공연/이벤트 일정의 조회와 관리자 CRUD를 담당합니다. 이벤트 데이터는 사용자 일정 화면뿐 아니라 AI 혼잡도 예측의 `event_soon`, `minutes_to_next_event`, 공연 인기도 feature에도 영향을 줍니다.

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `getAllEvents()` | 전체 이벤트 목록 조회 | `EventController`, `OpsController`, `AdminDashboardService`, `AiCongestionService` |
| `createEvent(EventUpsertRequestDto)` | 새 이벤트 생성 | `AdminEventController`, `OpsController`, `AdminImportService` |
| `getEventById(Long)` | 이벤트 단건 조회 | `AdminActionService` |
| `updateEvent(Long, EventUpsertRequestDto)` | 이벤트 정보 수정 | `AdminEventController`, `OpsController`, `AdminImportService` |
| `deleteEvent(Long)` | 이벤트 삭제 | `AdminEventController`, `OpsController` |
| `broadcastEventUpdates()` | 이벤트 목록 변경 후 SSE 발행 | 관리자/운영자 변경 흐름 |

대표 흐름:

```text
EventPage / LineupPage / EventDetailPage
-> fetchEvents()
-> GET /api/events
-> EventController.getEvents()
-> EventService.getAllEvents()
-> EventRepository.findAll()
```

### 3.6 `AiCongestionService`

AI 혼잡도 예측과 방문 추천의 핵심 서비스입니다. 현재 축제 snapshot을 만들고, 부스별 feature를 생성한 뒤 Python RandomForest 모델 또는 fallback 결과를 결합해 추천 DTO를 만듭니다.

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `guide()` | 방문자용 AI 축제 가이드 생성. 추천 부스, 피해야 할 부스, 나중에 가면 좋은 부스를 묶음 | `AiGuideController`, `ChatService`, `OpsAiService` |
| `analyzeCurrent()` | 부스별 AI 혼잡도 예측 목록 생성 | `AiGuideController`, `AnalyticsPage` |

주요 내부 흐름:

```text
AiCongestionService.guide() / analyzeCurrent()
-> FestivalSnapshotService.current()
-> modelPredictions(snapshot, eventSoon)
-> PythonCongestionModelService.predictBatch()
-> analyzeBooth()
-> AiBoothRecommendationDto
```

대표 프론트 흐름:

```text
AnalyticsPage
-> fetchAiCongestionPredictions()
-> GET /api/ai/congestion/predictions
-> AiGuideController.congestionPredictions()
-> AiCongestionService.analyzeCurrent()
-> PythonCongestionModelService.predictBatch()
-> List<AiBoothRecommendationDto>
-> 30분 혼잡도 예측 카드 렌더링
```

### 3.7 `PythonCongestionModelService`

Java 서버에서 Python 기반 RandomForest 추론 스크립트를 실행하는 어댑터입니다. 모델 파일/스크립트 경로가 없거나 timeout이 발생하면 빈 결과를 반환하고, 상위 서비스가 fallback을 사용합니다.

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `predict(Map<String,Object>, List<String>)` | 단일 feature에 대한 모델 예측 요청 | 현재는 batch 흐름의 보조 형태 |
| `predictBatch(List<ModelPredictionRequest>)` | 여러 부스 feature를 임시 JSON 파일로 넘기고 Python 모델 결과를 부스 id별로 매핑 | `AiCongestionService` |
| `displayLevel(String)` | `LOW/NORMAL/BUSY/VERY_BUSY`를 화면 표시용 한국어 레벨로 변환 | 서비스 내부/표시 보조 |

대표 흐름:

```text
AiCongestionService.modelPredictions()
-> PythonCongestionModelService.predictBatch()
-> scripts/ml/predict_congestion.py 실행
-> exports/ml/models/random_forest_congestion_model.pkl 로드
-> predictedLevel, confidence, driftStatus 반환
-> AiModelPredictionDto
```

### 3.8 `FestivalSnapshotService`

AI 추천과 운영 분석에서 필요한 현재 축제 상태를 한 번에 묶어주는 snapshot 서비스입니다.

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `current()` | 현재 시각, 부스 목록, 공연 목록, 부스별 혼잡도, 예약 수를 하나의 `FestivalSnapshot`으로 구성 | `AiCongestionService`, `OpsAiService`, `ChatService` |
| `FestivalSnapshot.activeReservationCount(Long)` | 특정 부스의 활성 예약 수 계산 | AI 혼잡도/추천 계산 |
| `FestivalSnapshot.reservationCount(Long, ReservationStatus)` | 특정 상태의 예약 수 계산 | AI 혼잡도/추천 계산 |

대표 흐름:

```text
AiCongestionService
-> FestivalSnapshotService.current()
-> BoothService.getAllBooths()
-> EventService.getAllEvents()
-> BoothService.getAllCongestions()
-> BoothReservationRepository 집계
```

| 메서드 | 역할 | 주 호출 위치 |
|---|---|---|
| `answer(String question)` | 질문을 분석하고 관련 데이터 검색, OpenAI 호출 또는 fallback 답변 생성 | `ChatController`, `ChatPage`, `HomePage` |

```text
ChatPage / HomePage
```

## 6. 읽는 순서 추천

백엔드 흐름을 처음 파악할 때는 다음 순서로 보면 빠릅니다.

1. `frontend/src/api.js`에서 화면이 어떤 endpoint를 호출하는지 확인합니다.
2. `backend/src/main/java/com/festflow/backend/controller`에서 endpoint가 어떤 service method로 연결되는지 확인합니다.
3. 해당 `Service`의 public method를 보고 Repository, 외부 API, SSE, DTO 변환 흐름을 따라갑니다.
4. 응답 DTO 이름을 기준으로 프론트 페이지에서 어떤 state와 UI에 쓰이는지 확인합니다.

AI 혼잡도처럼 여러 서비스가 얽힌 기능은 `AiGuideController -> AiCongestionService -> FestivalSnapshotService -> PythonCongestionModelService -> AiBoothRecommendationDto -> AnalyticsPage` 흐름을 기준으로 보면 됩니다.
